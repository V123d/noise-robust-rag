## 1. QA 数据集生成 Prompt

**用途**：从平板品类评论语料中自动生成 200 条高质量中文 QA 测试对。

**调用位置**：`scripts/generate_qa_dataset.py` → `generate_qa_pairs()`

**Prompt 组成**：

### System Prompt

```
你是一个严格遵循指令的 JSON 数据序列化机器，只能输出由对象组成的 JSON Array。
```

### User Prompt（每批次略有不同，以下为第 1 批次示例）

```
你现在是一位极度苛刻、严谨的科研数据标注专家。我为你提供了一批包含丰富细节的真实平板买家评论。
你的任务是：深度挖掘这批评论里的细节事实，生成 50 条用于双盲评估的中文问答对，这是你的第 1 批次任务。
【生成约束条件】：
1. 请务必挖掘不同维度的用户疑问（例如屏幕显示、性能游戏、电池续航、发热、品控、物流售后等），不要重复。
2. user_input：模拟电商用户极其真实、口语化的提问。
3. reference：作为 Ground Truth（金标准），它必须是100%基于下方评论内容提炼出的客观陈述。如果评论中包含不同的正负反馈，需综合陈述，绝不可自己编造。
4. 强制返回格式：不要包含任何多余的开场白或解释代码块，请直接返回一个严谨的 JSON 数组结构。
【希望输出的 JSON 结构参考如下】：
[
  {"user_input": "这台平板屏幕长时间看刺眼吗？", "reference": "根据用户反馈，屏幕显示清晰并具备护眼模式，暂无大量认为极其刺眼的不良反馈。"}
]

【供你参考的极长买家评论片段库】：
<此处嵌入 3000 条随机采样的平板评论，总 token 数约 5 万>
```

**关键参数说明**：

| 参数 | 值 | 说明 |
|---|---|---|
| 模型 | qwen-plus | 通义千问 plus 版本 |
| temperature | 0.6 ~ 0.9 | 第 1-4 批次依次递增，保证多样性 |
| max_tokens | 未设上限 | 由模型自行决定 |
| 输出格式 | JSON Array | 强制校验，不允许 Markdown 代码块包裹 |

**质量控制措施**：

- 每批次 50 条，共 4 批次，最终去重截断至 200 条
- JSON 解析失败时打印错误并跳过该批次
- API 调用间隔 3 秒，防止触发速率限制

## 2. 防幻觉答案生成 Prompt

**用途**：将检索到的高质量上下文与用户查询融合为最终 Prompt，驱动 LLM 生成事实一致的回答。

**调用位置**：`scripts/04_llm_generation.py` → `RAGGenerator.build_prompt()` / `RAGGenerator.generate_answer()`

### System Prompt（防幻觉约束）

```
你是一个严谨的电商智能客服助手。
【核心任务】：请严格基于以下提供的【真实用户评论证据】来回答用户的问题。
【严格约束】：
1. 你的回答必须100%忠实于提供的证据，绝不能捏造、发散或使用你的内在先验知识。
2. 如果提供的证据中没有包含回答问题所需的信息，请直接回答"根据已有信息，无法得出结论"，绝不能强行猜测。
3. 综合证据中的多方观点，给出客观、中立的总结。
```

### User Prompt 模板

```
【真实用户评论证据】:
证据 1: <第 1 条上下文>
证据 2: <第 2 条上下文>
...
证据 N: <第 N 条上下文>

【用户提问】: <用户原始查询>

请给出你的回答：
```

**Context 构造说明**：

- 上下文来自 `dynamic_truncate` 的输出（通常 1~5 条）
- 每条上下文格式化为 `证据 {i+1}: {text}`
- 若上下文中包含 (doc_id, score) 元组，则只取 text 部分

**LLM 调用参数**：

| 参数 | 值 | 说明 |
|---|---|---|
| 模型 | qwen-plus | 通义千问 plus 版本 |
| temperature | 0.1 | 极低温度，保证生成确定性 |
| max_tokens | 512 | 限制最大生成长度 |
| timeout | 30s | 单次调用超时 |
| max_retries | 3 | 失败自动重试次数 |

**容错设计**：

- 检索结果为空时，直接返回兜底拒绝回答
- API 调用失败时，返回错误信息字符串

## 3. RAGAS 评估 Prompt 模板

**用途**：RAGAS 框架使用强 LLM（GPT-4）作为自动评估器，对生成的答案进行四维度评分。

**调用位置**：`notebooks/05_ragas_evaluation.ipynb`（底层调用 `ragas` 库的 `evaluate()` 函数）

> ⚠️ RAGAS 框架内部使用专属 Prompt，RAGAS 官方不对外暴露这些 Prompt 的完整文本。以下内容为基于 RAGAS 论文（Es et al., 2023）重构的指标定义与近似 Prompt 模板，供理解评估机理参考，不等于框架实际调用文本。

### Faithfulness（忠实度）评估逻辑

**定义**：将答案拆解为若干原子主张，逐一判断是否可由上下文直接推理支撑。

**近似 Prompt 模板**：

```
你是一个严谨的事实核查助手。请仔细阅读以下【上下文】和【答案】，判断答案中每个陈述是否有上下文的直接支撑。
请逐条列出：
- 如果答案中某个句子可以从上下文中直接推导，则标注为"有支撑"
- 如果答案中某个句子在上下文中没有直接依据，则标注为"无支撑/幻觉"
最后给出比例：有支撑句子数 / 答案总句子数 = 忠实度得分（0~1）

【上下文】：
<检索到的上下文文本>

【答案】：
<LLM 生成的回答>

请输出 JSON 格式：{"faithfulness_score": 0.XX, "details": [{"sentence": "...", "supported": true/false}, ...]}
```

### Answer Relevancy（答案相关性）评估逻辑

**定义**：反向生成多个与答案相关的问题，计算与原始问题的语义余弦相似度。

**近似 Prompt 模板**：

```
你是一个问答系统评估专家。
原始问题：<用户原始查询>
待评估答案：<LLM 生成的回答>

请根据答案反推，如果要得到这个答案，用户最可能提出哪 3 个不同的问题？
请以 JSON 数组格式输出：
{"generated_questions": ["问题1", "问题2", "问题3"]}
```

随后计算「反推问题」与「原始问题」的余弦相似度（使用 embedding 模型），取平均作为 Answer Relevancy 分数。

### Context Precision（上下文精确度）评估逻辑

**定义**：相关文档在检索结果中的排序位置越靠前，精确度越高。

**近似 Prompt 模板**：

```
你是一个信息检索评估专家。请判断以下每条上下文对于回答用户问题的重要程度。
用户问题：<用户原始查询>
上下文列表：
  [1] <文档1>
  [2] <文档2>
  ...
请输出每条上下文的 Relevance Score（0 或 1，1=相关，0=无关）：
{"relevance_scores": [1, 0, 1, 0, ...]}
```

精确度计算公式（加权平均）：

$$
\text{Context Precision@k} = \frac{\sum_{i=1}^{k} (\text{Relevance@i} \times \text{Precision@i})}{\sum_{i=1}^{k} \text{Relevance@i}}
$$

### Context Recall（上下文召回率）评估逻辑

**定义**：参考文本（Ground Truth）中能被上下文覆盖的信息比例。

**近似 Prompt 模板**：

```
你是一个问答系统评估专家。请判断以下【参考文本】（金标准答案）中的信息，有多少比例可以被【上下文】所覆盖。
【参考文本】：
<reference>

【上下文】：
<检索到的上下文>

请给出召回率得分（0~1）：
{"context_recall_score": 0.XX, "reasoning": "..."}
```
